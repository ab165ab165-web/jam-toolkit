## 1. AI 工具使用日志模板（`ai-log.md`）

> 现场**边用边记**——别等晚上再补（补不出来）。推荐做法：每用完一次 AI 工具，**30 秒填一行**到 `ai-log.md`。
> 提交时整份塞进网盘 → `docs/ai-log.md`。

### 字段定义（与提交要求对齐）

| 字段 | 是什么 | 怎么记 |
|---|---|---|
| **时间** | 用完一次 AI 的本地时刻（精确到分） | `2026-10-17 10:42` |
| **工具** | 哪个 AI：Codely / Codex / Claude / Gemini / TJGenerators / etc. | 写全名 + 赛道名（如 `Codely` 写 `Codely Basic`，别写「AI」） |
| **应用环节** | 这条 AI 用在开发的**哪一步** | 用枚举：需求/设计/代码/美术/音频/视频/构建/调试/文档 |
| **输入的 prompt 摘要** | 你**确实发了什么**（不是事后回忆） | 1–3 句核心描述 + 关键约束；超长 prompt 存 `prompts/pXXX.md` 留索引 |
| **生成内容** | AI **给了什么**（代码/图片/音频/…） | 1 句核心结果 + 文件路径（如 `Assets/Scripts/Player/PlayerController.cs`） |
| **是否采用** | 最终是否落进交付版本 | ✅ 采用 / 🔁 改后采用 / ❌ 弃用 |
| **效果对比** | 不用 AI vs 用 AI 的实际差距 | 一句话量化：行数 / 用时 / 视觉差 / bug 数 |

### 模板（一行一次使用）

```markdown
| # | 时间 | 工具 | 环节 | prompt 摘要 | 生成内容 | 是否采用 | 效果对比 |
|---|---|---|---|---|---|---|---|
| 001 | 2026-10-17 10:42 | Codely Basic | 代码 | 「写一个 2D 横版跳跃角色，含土狼时间 0.1s、跳跃缓冲 0.15s、可变跳高」 | `PlayerController.cs` 128 行 | 略改 | 手写要 40min；Codely 3min；跳感更稳（手感更顺） |
| 002 | 2026-10-17 11:15 | TJGenerators (Image, SeeDream) | 美术 | 「中国山村·晒谷场·低饱和水墨风·俯瞰」seed 17 | `Assets/Art/Concept/01_normal.png` | ✅ 直接采用 | 一遍过，省 1h 概念稿 |
| 003 | 2026-10-17 14:03 | TJGenerators (SFX) | 音频 | 「脚步声·木屐·室内·走路·2s」 | `Assets/Audio/sfx/step_001.wav` | 🔁 改音量 | 默认偏响，Gain 调到 -6dB |
| 004 | 2026-10-17 17:50 | Codely | 代码 | 「实现 2D Light2D 强度从 1.0 渐变到 0.2，3s 缓动」 | `LightingFlicker.cs` 34 行 | ✅ 直接采用 | 自写要 15min；Codely 2min |
| 005 | 2026-10-17 22:10 | Codex | 文档 | 「按提交要求生成 AI 工具说明表格」 | `docs/ai-tools-section.md` | 改后采用 | 表格骨架对了，文案要人工改一遍 |
| … |  |  |  |  |  |  |  |
```

### 现场使用规范（防漏）

- [ ] 开赛**第一件事**：在 `docs/ai-log.md` 写一行 `# AI-Log`，表头复制上面 8 列。
- [ ] 每用一次 AI → 立刻填一行（哪怕只 30 秒，也别攒到结尾）。
- [ ] 长 prompt 另存 `prompts/<编号>.md`，日志里只写 `见 prompts/001.md`。
- [ ] 当日 22:00 / 次日 02:00 / 提交前各 review 一遍，**只补不删**（删了看不出真实过程）。
- [ ] 提交前把表格**导出一张 PNG**（截图便于评委扫读），原 `.md` 一并放网盘。

## 2. 演示视频分镜/脚本模板（`demo.mp4`，3–5min，**必交 + 必须含 AI 录屏段**）

> 总时长 **3 分 30 秒 – 4 分 30 秒**之间最佳（评委看到 5min 容易拖到倒计时）。
> **硬要求**：视频里**必须有一段可识别的「AI 辅助开发过程录屏」**——Codely+ 赛道要求是 **Codely 录屏**；AI+ 赛道是任意 AI 录屏。
> **封面**固定 **16:9 1920×1080**（见 §4）。

### 分镜表（直接照着录）

| # | 段落 | 时长 | 画面 | 旁白/字幕 | 素材来源 |
|---|---|---|---|---|---|
| 1 | **开场** | 0:00–0:10 | 黑场淡入 → 作品名（中文+英文）→ 队名 / 队员 / 主题（题目） | 「作品名 · X 队 · 2026 上海站 24h Vibe Coding」 | `cover.png` + 标题字 |
| 2 | **一句话玩法** | 0:10–0:25 | 单帧定格 + 玩法动图 GIF 循环 | 「这是一款……玩家通过……触发……」 | `shots/shot-02-gameplay.png` 或 `docs/gameplay.gif` |
| 3 | **核心循环实机** | 0:25–1:30 | 主菜单 → 进游戏 → 教学关 → 正常态 → 触发异常（笔触切换）→ 终局（玩家被写进场景） | 无旁白，只贴关键键位/状态字幕（点哪/异常态触发条件） | 实机 `Play Mode` 录屏（见 §3.3） |
| 4 | **AI 辅助开发录屏** ⭐必交 | 1:30–2:30 | Codely 对话框 + 编辑器 Project/Console 联动；或 TJGenerators 生成图的过程 | 「我们用 Codely 写了核心玩法……」  灯光段用箭头标出生成的代码 / 资源 | Codely 历史 + Editor 录屏（详见 §3） |
| 5 | **技术亮点 30s** | 2:30–3:00 | 快速闪：URP 2D 光照切换 / HitStop / 笔触渐变 / Cinemachine 跟拍 | 字幕：「同机位只改一处 · 2D 光照驱动恐怖」 | `shots/shot-03-abnormal.png` + Editor |
| 6 | **团队 + 致谢** | 3:00–3:20 | 队员头像/名字 + 工具栈 Logo（团结 / Codely / TJGenerators / 开源素材） | 「X 队 · 2 人 24h · 团结引擎 + Codely」 | 提前做好的 end-card |
| 7 | **邀请试玩 + 结尾卡** | 3:20–3:30 | 黑场 → 「扫描/点链接试玩」+ 提交平台标识 | 「完整试玩见百度网盘 · 提取码 UCDC」 | end-card |

### 录制规范（现场通用）

- 分辨率：**1920×1080**（1080p）；不要 4K（评委拖不动，文件巨大）。
- 帧率：**30fps**；UI 类动态画面建议 **60fps**（HitStop 顿挫更顺）。
- 编码：**H.264 / MP4**；码率 **8–12 Mbps**；**禁用 H.265**（部分评委机器解不动）。
- 音频：48kHz / AAC / 128kbps；现场噪音大可**只配字幕不配音**。
- 文件大小：**≤ 500MB**（网盘 + 平台上传速度考虑）；分段录，后期剪。
- 含 AI 录屏段（**最关键一段**）：
  - Codely+ 赛道 → 必含 **Codely 对话 + Editor 写代码 / 改场景** 的录屏。
  - AI+ 赛道 → 含任何 AI 工具使用画面（如 TJGenerators 出图过程）。
  - **全程保留时间戳 / 工具水印**，让评委能**肉眼识别**。

### 推荐剪辑工具（任选）

| 工具 | 平台 | 用途 |
|---|---|---|
| **OBS Studio** | Win / Mac / Linux | 录制（Project/Game 窗口）、直播推流 |
| **FFmpeg** | CLI | 截片段、合并、转码、压大小 |
| **DaVinci Resolve** | Win / Mac | 剪辑 + 调色 + 字幕（免费） |
| **Shotcut** | Win / Mac / Linux | 轻量剪辑，开源 |
| **剪映 / CapCut** | Win / Mac | 中文用户最熟，上字幕最快 |

## 3. 作品说明文档 PDF 骨架（`work-description.pdf`）

> **这是评委最先看的一份**——决定要不要继续读 / 玩。把模板拉好，1h 内能填完。

### 文档总览（5–7 页，每页字数 ≤ 400）

| 节 | 标题 | 写什么 | 字数控制 |
|---|---|---|---|
| **封面** | 项目名 / 一句话玩法 / 队名 / 队员 / 赛道 / 日期 | 一张 `cover.png` + 4 行信息 | 半页 |
| **1 项目简介** | 项目名 + 主题 + 一段话定位 | 题材 + 平台 + 类型 + 时长（≤ 3min）；**3 句话讲清给谁玩、玩什么、玩多久** | 200–300 字 |
| **2 核心玩法** | 玩什么 + 怎么玩 + 为什么上头 | 核心动词（单动词）+ 闭环路径 + 一张 GIF/图示 | 300–400 字 + 1–2 张图 |
| **3 技术亮点** | 用了什么 + 为什么选它 + 做了什么 | 引擎版本 / 渲染管线 / 关键模块 / 自研组件；每条 1 段 | 300–400 字 |
| **4 AI 工具说明 + 对比 ⭐** | 用了哪些 + 用在什么环节 + AI 出 vs 最终 + 是否采用 | **Codely+ 赛道此节必须含 Token 用量截图**（见 13-onsite-ops §2） | 400–500 字 + 1–2 张截图 |
| **5 团队介绍** | 队员 + 分工 + 沟通方式 | 每人 2 行：名字 + 角色 + 一句话贡献 | 100–150 字 |
| **6 素材来源** | 用了哪些第三方 + 协议 + 路径 | 表格：素材 / 来源 / License / 路径；引用 `assets/LICENSES.md` | 100–200 字 + 1 张表 |
| **7（可选）商业化 / 后续** | 迭代方向 / 玩法扩展 | 1 段，**不写也行**（不影响评分） | 100 字 |

### 字号/排版建议

- 正文：**宋体 / 思源黑体 11–12pt**，1.4–1.5 倍行距。
- 标题：粗体 14–18pt；节标题 ≤ 3 级。
- 图：清晰可读 ≥ 800px 宽；带 1 行说明文字。
- PDF 大小：**≤ 10MB**；评委打不开 = 扣分。
- 导出工具：Typora / Notion / Word / LaTeX / Pandoc（Markdown → PDF）任选。

### ⚠️ 必交的几张图（提前列好清单）

- [ ] 项目截图（正常态）≥ 2 张
- [ ] 项目截图（异常态 / 关键 UI）≥ 1 张
- [ ] Editor 工程截图 ≥ 1 张（**验证用了团结引擎**——评分的硬指标）
- [ ] Codely+ 赛道：Token 用量截图 ≥ 1 张（详见 13 §2）

## 4. 封面口径（统一）

> **全队所有视觉物料用同一张 16:9 封面**，避免出现「视频封面 16:9 / 提交表单 1:1 / 网盘缩略 21:9」的混乱。

| 项 | 值 |
|---|---|
| **比例** | **16:9**（硬要求，jpg/png） |
| **建议尺寸** | **1920×1080**（视频封面 / 主视觉）/ 1280×720（缩略 / 兜底） |
| **格式** | jpg / png；**png** 留透明背景适用场景 |
| **大小** | **≤ 1MB**（提交表单 / 网盘缩略图加载更稳） |
| **一句话** | **封面要一句话讲清玩什么**——主角 + 动作 + 输赢信号（例：「山村一日 · 你每看一遍 · 村子多一处不对劲」） |
| **禁区** | 无文字堆砌 / 无 4+ 元素拼贴 / 无版权不明素材 / 无 AI 水印未擦 |
| **字体** | Bebas Neue / Press Start 2P / 思源黑体 / LXGW WenKai（已备，见 `assets/fonts/`） |

### 标题/文字层级（封面三选一）

1. **大字版**（最稳）：主标题字号占封面宽度 1/3，副标题 1/8，留白充足。
2. **极简版**：只放「作品名 + 队名」，**不带玩法文案**（玩法放视频 0:10 段）。
3. **动感版**：主图 + 半透明色块压底 + 主标题（适合 PC/小游戏横版）。
