## 2. Codely Token 用量查看位置 + 截图表怎么做

> **Codely+ 赛道必交**：Token 用量截图 + Codely 辅助开发录屏。**两样都缺 = 直接判无效 / 重扣分**（见 06-competition-rules §2 / §4.3）。

### 2.1 三种查 Token 用量的路径（按优先级排）

> **官方有据口径**（2026-10-15 验证）：
> - 官方 CLI 仅暴露 `mcp` / `extensions` / `serve` 等会话内指令；`codely account usage` / `codely account stats` **不在官方 CLI 中**（npm `@unity-china/codely-cli` 仅列 `/help` `/clear` `/compress` `/stats` `/mcp*` 等 slash 命令）。
> - 用量查询走 GUI：`Codely 对话框 `/` → Account usage`，或网页 `https://codely.tuanjie.cn/dashboard/usage`（登录态生效）。

| # | 路径 | 怎么进 | 截图要点 |
|---|---|---|---|
| **A** | **网页端** `www.codely.tuanjie.cn` → 右上角**「我的」** → 「**账户与用量**」 | 浏览器登录，与 Editor 同账号 | 整页截图（带 URL、账号、时间） |
| **B** | **用量页直链** `https://codely.tuanjie.cn/dashboard/usage` | 浏览器登录态直接进 | 整页截图（带 URL） |
| **C** | **Codely 对话框 `/` → Account usage** | 在 Cowork / Editor / VSCode 集成内敲 `/` 选 Account usage | 截完整面板 + 时间 |

> **最稳的截图组合**：
> 1. **A 或 B 全页截图**（必交，账单级证据）→
> 2. **C 「/ → Account usage」面板截图**（GUI 过程证据）→
> 3. **Codely 对话框右侧栏**进度条（任务级实时证据）

### 2.2 截图操作步骤（**照此 5 步**）

1. 浏览器开 `www.codely.tuanjie.cn`，**确认右上角「我的」能点开**（登录态有效）。
2. 点开「**账户与用量**」→ 看到「已用积分 / 总额度 / 周期 / 用量曲线」。
3. **整页截图**（Win: `Win + Shift + S`；Mac: `Cmd + Shift + 4`），存为 `docs/token-usage.png`。
4. 再到 **Codely 对话框**敲 `/` → 选 **Account usage**，截一张带时间戳的**面板**，存 `docs/token-account-usage.png`。
5. 在 Cocnely 对话中跑一段任务时，截 Codely 对话框右侧栏**实时进度条**，存 `docs/token-progress-final.png`。

### 2.3 截图**必带**的元素（缺一不可）

| 元素 | 怎么保证有 |
|---|---|
| **账号 ID / 队名** | 截全页时右上角账号菜单可见 |
| **日期 / 时间** | Win 任务栏 / Mac 菜单栏 时间；或截图工具自带时间戳 |
| **用量数值**（不是 0 / 不是「加载中」） | 等页面加载完再截 |
| **URL**（`codely.tuanjie.cn`） | 浏览器地址栏 |

### 2.4 Codely 录屏段怎么进视频（详见 12 §2 分镜表第 4 段）

- **片段时长**：30s–60s，**不能 5 秒凑数**（评委一眼看出诚意）。
- **必含**：
  - Codely 对话框输入 prompt（清晰可见文字）。
  - Editor 同步出现：代码新增 / Console 报错 / 场景物体生成。
  - 右上角时间戳（肉眼能识别的开发时刻）。
- **剪辑要点**：录屏段不要用快进，要**正常速度 + 关键节点轻放慢**。

### 2.5 ⚠️ 待现场确认项

- **Codely 现场 Token 发放方式**：是主办注入到账号？还是扫码领取？**以上海站现场口径为准**——本表 §1.1 第 4 步「验证账号」时请同步确认。
- 官方文档未明确写「Token 用量在哪个 URL」——A 路径「账户与用量」**为常见做法**（见 codely-docs FAQ），**具体页面名以现场为准**。
- **Codely+ 赛道是否锁单赛道 / 能否中途切**——见 07-track-selection。

## 3. 录屏方法（**全流程都要录**）

### 3.1 录屏三件套（推荐）

| 工具 | 装/用 | 用在哪 |
|---|---|---|
| **OBS Studio**（开源） | 现场装好；设置：1920×1080 / 30fps / MP4（H.264） | 全程录 Editor + Game 窗口 |
| **Unity Recorder 包**（官方插件） | Package Manager 装 `com.unity.recorder` | Play 模式录游戏窗口（更稳、更不卡） |
| **FFmpeg**（CLI） | 截片 / 合并 / 转码 / 压大小 | 后期剪辑用 |

### 3.2 OBS 关键设置（**先试一次**）

- 来源 = 「**窗口捕获**」（捕 Editor）+ 「**游戏捕获**」（捕 Game 窗口）。
- 输出 = `mp4`，码率 **8000–12000 Kbps**，编码 **H.264**，**禁用 H.265**。
- 分辨率 1920×1080；FPS 30。
- 录制路径 = 工程外**独立文件夹**（不要录到 `Assets/` 内，每行触发全量重导）。

### 3.3 怎么开 / 怎么停（**最简单的口令**）

- 开录 → 「**开始录屏**」—— 谁负责喊，谁负责按 OBS。
- 停录 → 「**结束**」—— 仅用于提交前。
- **断录** → 「**暂停**」—— 用于中途休息 / 同步节点，**不要随便停**（后期拼接会丢段）。

### 3.4 什么时候就得开录（**红线**）

| 时刻 | 必须录吗 | 为什么 |
|---|---|---|
| **T+0** 开赛 → 第一件事就开 | ✅ | 漏录 30min = 后期补不回来 |
| **写第一行代码 / 第一次 AI 调用** | ✅ | 录屏段要含 AI 辅助开发过程（评分点） |
| **每次 Codely 调用** | ✅（强烈建议） | Codely+ 赛道必交 Codely 录屏 |
| **生成关键素材**（角色 / 场景） | ✅ | TJGenerators 过程片段是亮点 |
| **Editor 报错 + AI 修复** | ✅ | 「AI debug」是评分 AI 维度加分项 |
| **休息 / 吃饭** | ❌（可停） | 浪费时间文件大小 |
| **提交前 2h** | ❌（可停） | 已在 §1.3 收尾 |
| **用 Office / 浏览器查资料** | ❌（可停） | 与项目无关 |

### 3.5 ⚠️ 待现场确认项

- 现场是否**强制要求统一录屏软件**（部分赛事会发指定录屏工具）——**以现场为准**。
- 录屏段在最终视频里**时长占比是否要求 ≥ 10%**——目前规则文本未明说，**30s–60s 是安全下限**。

## 4. 断网 / 工具失败预案（**每个风险点都给 A/B 路**）

### 4.1 Codely 崩 / 登录不上 / 队列堵死

| 现象 | 应急方案 |
|---|---|
| Editor 内 AI 对话框无响应 | **A**：重启 Editor + 重连；**B**：切到 **Cowork**（独立进程）；**C**：切到 **CLI** `codely` 命令直跑 |
| Token 用完 / 显示「积分不足」 | **A**：每日签到领积分（见 Codely 文档）；**B**：换**第三方 AI**（Codex / Claude / Gemini）继续开发，**必填入 `ai-log.md`** 标注赛道兼容性；**C**：手动写码（**保留过程录屏** 一样算 AI 维度） |
| 现场 Wi-Fi 弱 / 断网 | **A**：用手机 4G/5G 热点（**先测速**）；**B**：本地模型（**不在本赛范围**）；**C**：暂停 AI 段，**全部手写**，**但仍要录屏** |

### 4.2 TJGenerators 失败 / 排队 / 出图无关联

| 现象 | 应急方案 |
|---|---|
| TJGenerators 队列堵死（图生 15min+ 不出） | **A**：**降低输入**（少字、明确主体）；**B**：换**本地备料**（`hackathon-prep/open-assets/` 已备 SFK / 粒子 / UI 套件） |
| 3D 模型生成失败 / 段错误 | **A**：换用 **Tripo P1 默认参数**（face_limit=5000，pbr=false，export_uv=true）；**B**：用 **`generate_animated_character`（Meshy AI）** 仅人形；**C**：直接用 Kenney / CC0 模型库（已备） |
| 音频生成失败 | **A**：用 **`generate_sound_effect`** 重试 1 次；**B**：**降级到 sfx-generators**（`hackathon-prep/open-assets/sfx-generators/`——含 jfxr/Bfxr/ChipTone 离线工具链） |
| 视频生成失败 | **A**：**减时长**（≤ 5s）+ **降分辨率**；**B**：**改为图片序列 + 拼接**（FFmpeg）；**C**：**取消**——24h 不强求视频素材 |

### 4.3 没网（全程断）

| 环节 | 应急方案 |
|---|---|
| 团结 Hub 下载 | **A**：现场提供离线包？**问主办**；**B**：用本机已装引擎（已装 `2022.3.62t16`，跳过） |
| Codely / TJGenerators | **全断** → **改手动写码 + 用 hackathon-prep/ 本地备料**，**AI 工具说明里注明「断网转手动」**，**不影响 AI+ 赛道评分**（评「我主导，AI 加速」） |
| 包体 / 平台 SDK 下载 | **A**：用本机已下好的 `Library/` 缓存；**B**：**降到单平台构建**（PC 优先，WebGL 优先于小游戏） |
| 提交上传 | **A**：**手机热点上传**；**B**：**U盘 + 主办电脑**（多数赛事有备用提交通道） |

### 4.4 录屏失败 / OBS 卡死 / 文件损坏

| 现象 | 应急方案 |
|---|---|
| OBS 录制中途崩 | **A**：**Unity Recorder** 接管（Editor 内独立录）；**B**：**重启 OBS**（**设置自动分段录制**，5min 一段，崩了只丢一段） |
| 录屏文件损坏 | **A**：FFmpeg 修复 `ffmpeg -i broken.mp4 -c copy fixed.mp4`；**B**：**补录 AI 段**（重做 1–2 次 AI 调用录下来） |
| **录屏文件过大（> 2GB）** | **A**：**降低码率**（H.264 / 6000 Kbps）；**B**：**分段录**（每 4h 一段，10min 后归档）；**C**：**用 FFmpeg 重压** `-c:v libx264 -crf 23` |

### 4.5 构建失败 / 平台 SDK 缺

| 平台 | 应急方案 |
|---|---|
| **Windows 构建失败** | **A**：Player Settings 关 `IL2CPP` → 改 `Mono`（**包体大但能跑**）；**B**：删未用模块 / 关 Post-Processing 临时 |
| **WebGL 构建失败** | **A**：关 Strip Engine Code；**B**：删 shader 变体；**C**：降纹理 ASTC 等级 |
| **小游戏（微信/抖音）** | **A**：**直接改走 WebGL 提交**（评委机器可跑就行）；**B）：删 `Resources/` 资源改 Addressables；**C**：**单文件分包 ≤ 4MB** 主包限制 |

### 4.6 ⚠️ 通用兜底原则（**赛事级**）

- **任何应急方案都要写进 `ai-log.md`**：「因 X 故障，Y 工具转 Z 替代」。
- **任何替代方案都要保留录屏 / 截图证据**——「我用了 AI / 我主导开发」是评委看的。
- **任何决策要同步给队友**——14-team-and-platform §2 已约定「不私自改方案」。
